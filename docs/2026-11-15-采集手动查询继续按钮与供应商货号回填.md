# 采集手动查询、继续入口与供应商货号回填

## 本轮问题

v2 的互拓采集等待详情显示“自动队列已暂停”，但窗口里没有立即查询、继续队列或重试按钮。用户还要求人工确认供应商后，选品表货号不再一直为空。

## 查询与继续

- 商品详情“当前步骤”和“互拓采集”区域、商品卡片增加操作入口。等待时可点击“立即查询采集结果”，异常或停止后显示“重试查询原记录”；异常时保留“继续原任务 / 重试未完成项”。
- 全局队列暂停时显示“继续自动队列”。窗口打开期间暂停状态变化会刷新按钮，点击后当前商品窗口保持打开。
- 手动查询只访问当前商品已保存 ID 的原互拓采集记录，忽略30/60秒的下次定时计划，不发送新的采集提交。
- 队列暂停时也能查询单件。即使取得资料并进入“整理上架资料”，全局队列仍维持暂停，用户点击继续队列后才恢复后续处理。
- 定时处理与手动查询共用同一商品的执行锁，避免重复读取与并发推进。查询错误在当前窗口显示明确原因并提供重试。
- 保留原有任务/表行关联验证，任务属于其他表行或来源已变化时，不查询或修改其他商品。

## 货号回填

- 人工确认供应商时，候选已经带有供应商货号则立即补入空白本机任务并回写共享表；候选没有货号时，详情采集取得 `sku` 后补回。
- 已有旧任务可在手动查询原采集记录时补回已确认供应商货号，无需重做人工同款审核。
- 共享表服务增加 `supplierArticleNo` 工作流回填字段，要求当前绑定任务 ID 与版本均匹配。普通表格编辑仍不能修改已领取行的货号、链接与确认状态。
- 只补空白或回写相同货号；已有不同货号明确返回冲突，保留原值，不覆盖。确认人、来源链接和其他表格字段不变。
- 网页版与客户端共用表数据，回填后网页按既有刷新计划显示；客户端原任务对应行也更新。
