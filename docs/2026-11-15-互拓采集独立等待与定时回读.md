# 互拓采集独立等待与定时回读

## 问题与调整

用户截图中的任务已人工确认淘宝套图，但停在“取得互拓淘宝采集资料”，约两分钟后提示“采集等待超时，已保留商品 ID；重试只查询原记录”。原客户端在一个步骤中每 3 秒查询一次、最多 40 次，ERP 抓取稍慢就会转入待人工处理，并在等待期间持续占用当前自动处理任务位。

采集已经提交与采集结果已经齐全是两个状态，本轮拆成“提交互拓采集”和“等待互拓采集结果”。流程轨迹增加独立的“互拓采集”阶段，位于确认套图之后、整理互拓资料之前。

## 状态逻辑

1. 先按淘宝商品 ID 查询互拓平台商品爬虫原记录。查询失败不等于没有记录，不据此提交。
2. 没有记录且从未留下提交检查点时，先保存稳定商品 ID 与提交检查点，再提交采集。已有记录或已尝试提交的任务均不再自动提交。
3. 提交完成后进入等待状态并释放任务位。正常每 30 秒查询一次原采集记录；网络超时、连接失败、429、503 等临时异常改为 60 秒后查询。
4. 提交请求回执未知时也进入查询状态，不因为不知道提交结果而自动重发。关闭程序或重新登录后仍使用同一个 ID。
5. 不只判断记录是否存在；原记录须有可解析的商品预填资料、标题和图片。完整后读取原图列表，自动进入整理上架资料；原图列表临时读取失败也留在查询流程。
6. ERP 明确标记“采集失败”、登录或权限错误、货号或供应商冲突时停止自动查询，并显示具体原因。人工在 ERP 处理原记录后，可从原任务继续查询，不重新创建采集。
7. 正常等待不设置两分钟截止时间。程序运行且自动队列继续时按计划查询；暂停队列或退出程序期间停止。查询频率受本机队列并发限制，不为满足时刻同时堆积请求。

## 持久化与旧任务

- 保存采集商品 ID、开始时间、最近查询、下次查询、检查次数、查询间隔及最近错误。
- 当前商品详情展示等待原因、原商品 ID 和查询时间，不再出现无关的“补充供货资料”表单。
- 反复等待不重复追加同一条处理记录或反复回写相同在线表状态；状态改变和取得资料后同步表行。
- 旧版停在“采集等待超时”且仍保存商品 ID 的任务，客户端载入时恢复为定时查询状态，遵守原有队列暂停状态。
- 仍使用现有平台商品爬虫查询和原图接口，不新增接口，不走商品池同款检索；不改变草稿与人工待审核的后续规则。

## 关键文件

- `desktop/erp/client.mjs`：一次提交与一次只读查询分离，校验原商品与供应商身份。
- `desktop/buyer-providers.js`：回读采集资料和原图，区分临时错误与明确失败。
- `desktop/buyer-engine.js`：独立等待步骤、持久化查询计划、队列调度、暂停恢复和旧任务迁移。
- `desktop/buyer-workflow.js`：将采集状态提供给界面。
- `desktop/buyer-auto-renderer.js`、`desktop/style.css`：七阶段流程与采集等待状态展示。
