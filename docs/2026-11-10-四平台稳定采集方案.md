结论：四个平台当前样本的核心商品资料都有可直接提取的页面来源。要稳定采集，需要“按平台解析商品区域、触发并校验懒加载、保留字段证据、检查完整性、按错误类型重试”一起完成。本轮已验证专用规则可行，尚未修改或替换产品采集逻辑。

## 1. 统一两个入口，按平台提取

当前自动买手和人工确认后详情采集分别使用 `buyer-page.js` 与 `background.js` 内不同的采集函数，两者漏采和图片过滤表现不同。应共用同一套平台适配器，来源页和供应商详情仅使用不同的完整性要求。

页面资料优先级：平台商品区域内明确字段和 SKU 数据 → 平台结构化商品数据 → 有证据的页面文字 → 图片 OCR。模型用于整理成分、识别尺码图、解释冲突，不承担基础价格、货号、店铺和规格的唯一提取职责。

本轮已确认的页面定位：

| 平台 | 价格 / 货号 / 规格 | 商品图片范围 |
| --- | --- | --- |
| 网商园 | `.J_p_price`、`.item_sx .li a`、`.shop-info .name`、`#J_TSaleProp`、`.table-sku` | `.wsy-gallery .J_pic_open[href]`、当前主图、`#J_DivItemDesc` |
| 17 网 | `index-pifaPriceWrapper-`、`index-itemNoPanel-`、`index-goodsParamsWrapper-`、`index-detailSizeSelectorLabel-` 等组件 | 主图组件、颜色图、`index-detailWrapper-`；使用语义前缀而非完整构建哈希，并保留标签回退 |
| 青创网 | `.price_detail dd`、`.pro_att li`、`.shop-info a.link`、`.pro_size_item` | `.picsize a[data-big]`、商品详情 `img[lazyload]` |
| 衣衫汇 | `.art-num-text`、`.product-price-info .price strong i`、`.min-limit-price .p`、`.supplier-name a`、`data-color`、`.all-size` | `.small-img-item a[href]`、`.product-details-content img[data-url]` |

颜色必须读完整规格列表。青创网 `.J_clr` 只命中了当前选中的颜色；衣衫汇宽泛读取颜色区域内所有 span 会把数量标记 `x0` 混为颜色。诊断规则已改用商品属性和明确的 `data-color` 验证完整颜色。

## 2. 图片按用途采集，并验证加载完成

- 分开保存主图、颜色图、详情图、尺码图及视频，按商品区域取值，排除推荐、二维码、横幅与占位图。
- 青创网当前详情图实际地址在 `lazyload`；衣衫汇在 `data-url`。现有两个采集器均未读取这些属性。
- 网商园缩略图对应的原图已放在 `.J_pic_open` 链接中，应直接读取，不靠猜测或替换缩略图后缀。
- 17 网本轮有 30 个详情图片节点，初始只有 5 个真实图片地址，其余为 `preview_100_100` 占位图。通过正常页面交互滚动到中部及末尾后，取得 30 个真实地址，最终占位图为 0。
- 对确实需要滚动加载的页面，使用有限次数的滚动与重新读取，按图片节点数、真实地址数、占位图数确认完成；达到上限则返回“部分采集”，保留已取得内容。
- 下载环节继续保留平台/CDN 校验、内容类型、尺寸、解码和去重。签名参数不能任意删除；HTTP 到 HTTPS 的转换仅对确认支持的图片域名进行。

主图就绪即可开始相似图比对；完整供应商资料就绪后才能继续整理上架资料。两者不能共用“有标题和一张图片即成功”的判断。

## 3. 保留价格语义、货号和证据

返回资料建议包含 `platform/productId/canonicalUrl`、标题、完整货号、供应商、供货价、阶梯价、最低限价、颜色、尺码、SKU 组合、成分原文及图片分组。每个关键字段附页面区域、原文、采集时间和来源类型。

青创网的 ¥158 是数量档位价格，衣衫汇的 ¥368 是最低限价，都不能直接当作本次拿货成本。应先保存价格类型、数量条件及可选规格，条件未确定时标记待核实。

还需要修改后续货号口径：当前 `desktop/buyer-evidence.js` 只接受英文字母、数字和 `/`，已验证它会拒绝真实货号 `YPD6711AB加棉套装`。提取、模型引用核验、人工补充、查重和 ERP 映射应一致保留原始货号；文件路径安全另行处理，不能为了路径方便截掉中文。ERP 的实际长度和字符支持仍需在只读契约或测试环境验证。

同页冲突要保留：衣衫汇示例既有“棉100%”，也有“成份：棉 绒毛聚酯”，详情文字还有不同尺码表述。应返回冲突及对应原文供人工核对，不能靠模型猜成无冲突资料。

## 4. 区分完成、缺项和外部阻塞

建议将页面状态与资料质量分别保存：

- 页面状态：加载中、可读取、需登录、需验证、配额不足、商品下架、网络失败、模板不支持。
- 资料质量：主图就绪、核心字段齐全、图集未完整、字段有缺失、存在冲突。

应验证返回商品 ID 与任务相符；缺项和错误原因要随回执保存。搜索候选回填的价格或店铺必须标注来源，避免界面看似齐全但详情采集其实失败。

内置浏览器本轮已登录，仅证明该浏览器会话有效。正式软件当前由配对浏览器扩展执行采集，必须在实际执行扩展的浏览器会话中核对登录和回执；不能假定登录状态跨浏览器自动共享。

## 5. 重试只针对可恢复错误

沿用用户要求的重试方式：网络异常、临时超时或尚未完成加载时，自动重试最多 3 次；超出后等待人工点击，开启新一轮 3 次。保留已成功的字段和图片，仅重试缺项。

登录、验证码、认证或配额不足应直接标明下一步，处理完后继续原任务。结构变更且定位器持续失效时记录模板问题，不能一直刷新。

青创网图搜需单独验收“页面就绪 → 图片处理 → 上传 → 搜索请求 → 结果解析 → 回执”。当前已有阶段变量，但超时错误仍是通用 25 秒提示；应把失败阶段、耗时和可重试性传回桌面端，确认回调、响应结构及配额分支。正式重试不能反复消耗已经成功的上传或搜图次数。

## 实施顺序与验收

1. 统一采集器，先补四个平台核心字段、价格语义、真实图片属性与商品区域隔离。
2. 增加懒加载完整性、资料质量状态、货号兼容和跨回执字段保留。
3. 补阶段诊断、可恢复错误重试和原任务继续；单独定位青创网搜索超时。
4. 用真实模板的脱敏固定样本测试选中/未选中颜色、占位图、二维码、阶梯价、最低限价、中文货号及冲突，替换目前只依赖理想 JSON-LD 页面的验收方式。
5. 在软件配对插件中逐平台完成真实任务下发、采集回执、落盘回读及缺项重试；各平台覆盖多件商品和至少不同规格/价格模板。随后才做真实模型事实整理和安装包验收。

建议验收口径为“已支持模板内能重复采集正确资料；页面有变化或外部阻塞时能准确报告并恢复”，不承诺第三方网站永远不变或所有商品资料必然齐全。
