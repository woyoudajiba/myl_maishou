# 供应商名称匹配与模型统一填表

日期：2026-11-16。

后续发布状态：本功能已随 `26.11.16-v2` 完成客户端、配套插件及正式云端代理发布；下文保留实现阶段的证据与边界，最终交付见 `2026-11-16-v2-打包与部署验收.md`。

## 用户确认与真实原因

用户要求取回互拓候选与字段选项，让模型统一填写后直接保存正式互拓待审核，人工主要在互拓检查；软件可保留查看能力，不增加逐项确认步骤。用户进一步确认该件商品“动感地带是档口名字”。

实际网页的 `.shop-info .name` 为 `国际服装城11020`，`.shop-info .subname span[title]` 为 `动感地带旗舰店`。之前采集器只取前者，将档口位置当作供应商名；随后互拓匹配又要求该名字精确相等，导致卡在“供应商未唯一对应互拓档案”。

正式 ERP 的按名接口查询 `国际服装城11020` 返回空数组；查询 `国际服装城` 只返回另一个档口 `国际服装城1X16`，不能替代当前供应商。完整目录接口 `GET /erp/supplier-infos/getSupplier` 返回名称到仓库及缩写的映射，共 5,793 项，其中 5,792 项具有可用名称及缩写。目录中包含 `动感地带旗舰店`；按其名字查询已审核启用列表，返回 supplier_id 4987、supplierAb `DGDDQJD`。目录仓库为 `CS`。

## 已实现的流程

1. 网商园采集优先取 `.subname` 的真实店名，`boothName` 单独保留 `.name` 的档口位置。页面原文、属性中的店名、档口位置及发货地继续保留。
2. 读取并缓存当前账号可见完整供应商目录五分钟。目录已齐全时不重复执行多个关键词请求；不可用时以已有按名接口回退，不把接口异常当成没有供应商。
3. 在本地按店名、页面原文、供应商别名等证据排序，给模型最多 80 个相关候选，保留仓库、名称和缩写。完整目录在本地筛选，不把几千个无关商家与私有联系信息一起发送。
4. 第一轮模型一起选择真实供应商和互拓服装类别。供应商必须从候选选择，并引用当前商品页原文。校验原文能对应店名，再到互拓已审核启用列表确认相同名称与缩写；不因同一服装城或衣服同款替换供货商。
5. 取得该类别全部动态控件及当前互拓字典，将已核实商品事实、图片、选中供应商和所有字段选项一起交给模型统一填写。描述类字段可根据图片和原文判断；货号、供货价、颜色尺码、成分比例保持供应商事实，不能由模型改写或编造质检、品牌凭证。
6. 自动修正单选 / 多选形状以及 label / value 对应；按真实字典处理仓库和尺码。选中互拓供应商档案中的仓库优先。重复的同名材质标签去重，保留原比例；同名但不同身份的颜色仍需明确匹配。
7. 本机验证发现可由现有选项补齐的必填项时，自动再补填一次，只处理缺失项，减少软件人工处理。模型暂时失败仍沿用原自动重试 3 次的规则；手动继续会重置当前映射阶段的重试预算。
8. 资料通过验证后直接沿用上一轮的正式互拓待审核保存流程，无新增软件确认步骤。例外时保留候选和选择依据；商品详情可展开查看，历史任务可从已有原文恢复名称匹配，无需先重跑平台搜索。

## 发布及真实商品边界

本轮实现和验证已经完成，尚未打包客户端、上传或部署这轮新增的供应商目录代理路线，也没有修改正在运行的用户本机任务。当前安装版不会自动获得客户端采集、匹配和填表改动，需要与“直接保存互拓待审核”一起发布新版客户端、插件和云端代理。

真实模型验收只完成供应商选择，尚未执行真实全字段填表、付费图片比对、ERP 新增商品或最终上架。用户的目标流程为正式 ERP 待审核，最终审核仍在 ERP 完成；本轮未改成跳过 ERP 审核。
