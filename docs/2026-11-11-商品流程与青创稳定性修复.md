# 商品流程、候选图片布局与青创网响应处理

本轮依据用户三张截图实现源码改动：青创网回调超时、候选区域右侧大面积空白、弹窗滚动后无法关闭，以及商品流程入口和处理记录难找。未递增版本、打包、上传或部署；线上安装版本仍为26.11.10-v4。

## 商品与流程的对应关系

- 以现有“在线表ID + 行ID + 任务ID”关联作为唯一依据，沿用任务检查点，不另外创建一套虚拟文件夹或重复任务。实际商品文件夹仍由现有文件保存流程管理。
- 点击已保存商品行的行号、状态、只读货号/链接或空白处，即可打开该款商品流程；行获得焦点后也可按Enter打开。可编辑标题、备注以及原有操作按钮保留各自行为，单元格编辑不会被行跳转拦截。
- 详情顶部显示商品主图、标题、所属表行、状态、当前步骤与六阶段进度：读取链接图片 → 寻找供应商 → 取得供货资料 → 核对套图 → 整理互拓资料 → 进入待审核。
- “当前步骤、供应商图片、平台状态、供货资料、处理记录”常驻顶部。供货资料待补时直接定位补资料表单；处理记录按钮自动展开并定位最近记录。
- “返回表格”核验原任务关联后关闭详情并高亮原表行；同表原行已加载时不重建表格，不丢失尚未保存的备注。跨表或跨页且有未保存输入时阻止跳转并提示。
- 其他电脑的任务显示云表已同步的流程、状态及原因，只读查看，不在本机重复执行；原行定位失败时保留详情并显示原因。
- 本机进度随现有桌面快照更新到对应表行，保留输入框和焦点。引擎在进入处理中及等待原因变化时调用现有按任务绑定的表格回写，等待原因使用原有同步说明字段展示；相同等待状态不反复回写。

## 弹窗与候选图片

- 问题来自旧的左右两栏布局：右侧内容已移走，但候选仍占左侧窄栏。改为候选列表占满容器，宽窗口两列大图卡片，窄窗口一列；主图固定显示区不会被长按钮或详情图集拉成空白长条。
- 弹窗改为固定标题/导航区域及独立滚动内容区；“关闭”和“返回表格”始终可见。内容刷新保留当前滚动位置、已展开的处理记录；供货资料正在填写时不重建表单。
- 每组4条候选，支持上一组/下一组和当前范围，取消只展示前24条的限制，最多沿用现有500条候选上限。图片放大、链接图集、选择供应商和识别页跳转继续使用原接口。

## 青创网

- 用户截图确定的失败阶段是image_search：请求已提交后25秒内未等到原生回调；截图本身不能证明平台没有搜索，也不能据此把结果判为空。
- 青创网单次搜图等待由25秒增加为45秒，四平台总收尾由75秒调至110秒，以包含页面加载与上传时间。
- 保留原生回调、jqXHR.done及Promise.then接收方式；增加同源、相同搜图接口、相同ImgUrl的ajaxComplete响应观察，支持表单和JSON请求体。在原生帮助函数未回传结果但原请求返回时，读取这一次响应，不另发搜图请求。
- 响应观察不会匹配其他图片的搜索。成功、失败、取消和超时清理监听；取消时立即结束本次等待。
- 上传或搜图超时仍不自动重发不确定请求。额度、认证、HTTP失败与空结果的原有区分保留，不以“自动重试”绕过平台限制。
- 真实用户账号本轮未再次执行收费/计次搜图。未登录的公开搜图入口发生HTTPS转HTTP登录跳转，本轮未继续降级访问；没有借此读取或保存Cookie。
