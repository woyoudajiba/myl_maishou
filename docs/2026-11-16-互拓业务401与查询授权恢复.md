# 互拓业务 401 与查询授权恢复

日期：2026-11-16，时间为北京时间。

## 原因与证据

用户软件停在“采集查询失败：ERP 请求失败（HTTP 200，业务码 401）”，同时正式 ERP 中已能看到 D2603。两者并不矛盾：商品采集已经完成，但软件读取该商品时使用的接口授权被 ERP 拒绝。

本机任务日志记录 10:01:49、10:01:56、10:01:58 三次相同错误。线上旧网关仅检查 HTTP 状态码 401，未识别 HTTP 200 响应体中的 `code:401`。令牌在缓存的预计有效期内会被继续复用，也没有对被拒绝的只读请求重新授权并重查，因此反复查询仍会失败。

10:06 的真实正式环境只读探测，正常授权后返回商品及原图 HTTP 200 / code 0；OAuth 返回 expires_in 为 1799 秒。这证明商品仍存在且当前账号具备读取能力。现有证据不能区分原令牌为何提前被拒绝：可能是服务端撤销或其他登录等情况，不能据此断言为某一种机制。可确认的客户端 / 网关问题是没有处理 ERP 的业务码 401。

## 修复

- 同时识别 HTTP 401、数字业务码 401 和字符串业务码 "401"。
- GET 与两个明确只读的分页 POST 接口重新授权并最多重查一次；保持原请求体及范围。
- 优先使用 refresh_token；刷新失败时尝试一次保存的正常账号授权。
- 同一账号的并发请求共享授权过程，迟到的旧令牌错误复用新令牌；更新映射或服务设置时使相关缓存与未完成授权失效。
- 采集、新增草稿、上传、转换和删除请求遇授权错误时不自动重发，避免重复写入。
- 连续授权拒绝明确返回 ERP_AUTH_EXPIRED，与 TDL 登录失效分开，不因 ERP 业务 401 退出桌面账号。
- 账号连接检查也采用相同的授权恢复流程。
