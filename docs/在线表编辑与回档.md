# 在线表编辑与回档

## 当前异常的判断

截图中的“本机在线选品表服务暂不可用”来自桌面主进程请求云端服务时的统一网络错误文案，并不代表本机 43821 桥服务停止。云端表格使用 `/maishou/api/online-table`，本机桥服务负责浏览器插件，二者是独立连接。

本轮公开探针验证云端表格 `/health` 返回 200，未带 TDL 会话访问 `/api/tables` 返回预期的 401。当前服务可访问；这些证据无法还原截图发生时的具体网络原因，也不能替代当前账号的生产读写验收。

客户端原来会吞掉表格加载异常，刷新恢复后仍可能保留旧报错；周期快照还会覆盖表格自己的状态显示。修正后按域名解析、请求超时、证书错误、HTTP 鉴权失败分别提示，成功加载会清除旧异常，失败不会显示“刷新成功”。不关闭 HTTPS 校验，不显示登录令牌或原始异常中的敏感信息。

## 使用入口

- 商品录入与处理 → 在线选品表：在软件内查看共享行。
- 新增商品行：输入来源、链接、货号、标题、备注；展开“选品字段与商品文件夹编号”可填写日期、表格ID、供应商、运营编码、选品人、买手、销量、价格和仓库。
- 行内“保存”：保存货号、链接、标题、备注。“更多字段”打开其余字段。已领取任务的身份与目录字段只读。
- “撤销输入”：丢弃该行尚未保存的本机输入。未保存输入期间暂停周期刷新，手动刷新也保留原输入和原版本号；冲突时要求刷新，不能覆盖他人修改。
- “删除”：先确认再删除；删除记录可恢复。删除在线行不会取消自动任务，也不会删除互拓商品。
- “确认并提交”：先检查当前 TDL 账号的互拓配置，再确认和启动自动处理；普通保存或新增不会直接提交互拓。
- 已确认行若由另一台电脑处理到“供应商搜索/比对”异常，本机显示“打开链接”和“本机重新开始”。重新开始会原子改绑到本机新任务、保留行内容与旧电脑本地记录；只有供应商阶段异常允许接管，含互拓提交或不确定回执的任务不会开放此操作。本机任务会使用本机浏览器登录状态。
- “修改记录”：所有登录买手可查看操作人、时间、操作类型及字段前后值，支持加载更早记录。

## 保存和恢复逻辑

每次成功写入，在一个事务内完成数据变更、审计记录和表格版本递增，提交后才通知其他客户端。历史使用完整基线加增量记录，并定期保存完整检查点；不为每一次单行修改重复复制全表。

恢复点定义为“该条记录所对应操作之前”。例如误清空产生记录 #20，恢复 #20 就是找回清空之前的表；新增产生记录 #1，恢复 #1 将回到新增前的空表。列表明确使用“恢复操作前内容”避免误解。

管理员点击恢复后，先读取预览，再在系统确认框中显示找回、更新、移出的行数和任务保护说明。确认请求携带预览时的表格 revision；若期间有人编辑或任务回写，则拒绝并要求重新预览。恢复是整张表的操作，可能同时撤销后续其他人的业务字段编辑。

恢复前的状态也会留痕，因此可以撤销一次回档。删除使用软删除，保留原行和任务凭据；恢复后行版本只增加。即使行暂时被移出共享表，其原有任务绑定仍保留。

回档保留当前自动处理进度、任务ID、互拓编码；已领取行还保留来源、货号、目录字段及确认状态。未领取的恢复行重置为待确认，需要重新人工提交。表内回档不会撤销互拓中的草稿或商品。

共享任务会同步当前自动处理步骤。本机重新开始接口按共享行版本和原任务编号执行条件更新；旧设备、重复点击或并发操作不能再次接管。此功能需要桌面端和在线表服务都更新到支持跨设备重启的版本，部署文件按 `table-server/README.md` 的受控服务发布流程更新。

任务遇到人工编辑或回档造成的版本冲突时，仅在服务器确认仍属于同一任务后，重试处理状态、异常和互拓编码三个字段的回写；不能覆盖人工填写的标题、备注或其他业务字段。26.11.08-v1 起桌面端无需填写互拓连接参数，只显示云端连接状态。点击“打开互拓账号页面”，使用 TDL 登录后仅保存互拓账号和密码；公共 API、租户和 OAuth 由管理员在服务器统一维护。所属公司不要求填写，密码和密钥不下发到客户端。

## 日期和表格ID

固定模板导入的日期、表格ID、运营编码、供应商、操作人及表格字段，会保留到在线行、修改记录、导出文件和任务 origin 中。无表格ID的新行由服务按行序分配补零编号，用户可在领取前修改。

任务资料目录继续使用原规则：`买手/11.6/01`，取得互拓编码后再改名。请在同一天内使用不同的表格ID；已开始处理的行不能修改目录依据。

工作簿图片附件仍不作为在线表附件上传，商品图片从来源链接采集。原表价格和成本作为录入字段保留，不能作为供应商核验结论。

## 验证和上线边界

本轮在隔离的本地数据目录和测试 TDL 身份下验证：新增编辑、完整批量失败回滚、并发版本冲突、软删除恢复、撤销回档、超过单次导入上限的整表恢复、跨历史检查点和服务重启恢复、管理员权限以及回档后任务不重复领取。Electron 测试通过真实本地 HTTP 表服务，验证断网恢复、旧报错清除、输入保护、更多字段、修改详情、确认删除和回档。

连续空白行、商品计数和查找跳转已随 `26.11.07-v4` 配套发布桌面端和在线表服务。更新前使用 SQLite backup API 保存一致性备份，并在备份副本上验证新增、计数、查找和历史；生产数据行未用于测试删除或回档。历史从功能启用后的首次写入开始保存，不能补录之前从未记录的操作。修改记录不是数据库文件丢失或服务器磁盘故障的备份替代品。


## 连续空白行和查找

打开在线表后直接显示一组空白行，滚动到末尾、聚焦末尾或点击“继续添加空白行”会继续增加空白行。货号、标题、备注、日期、供应商和其他固定业务字段都可以先填或暂时留空。保存空白行会保留录入内容，但在线表的“商品数量”只统计商品链接不为空的行；空白链接行不能确认、领取或启动自动买手。

可以把 Excel 中的多行多列直接粘贴到货号、商品链接、标题、备注列，软件会先在本机标记未保存内容，再由“保存未保存行”一次写入并保留行顺序。粘贴超出当前页时先加载下一页，避免覆盖未显示数据。

“查找整张表”支持货号、商品链接、标题、备注、互拓编码和固定业务字段。查找后显示第几处匹配，并把对应行加载到表格、滚动定位和高亮；“上一处/下一处”在匹配结果之间切换。“跳到行号”用于直接定位指定表格行。Ctrl+F 会把焦点放到在线表查找框。
