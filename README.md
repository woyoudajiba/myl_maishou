# 找商品 · 精简工作台

Chrome / Edge 浏览器扩展，当前构建版本 **26.11.12-v1**，默认连接 Electron 本地桌面端。用一张或一组独立商品图片检索批发货源，再由视觉大模型把原图与候选图一起比较，展示商品细节、疑似同款与差异，并在已有成本时筛选更低价货源。

默认使用 Electron 桌面端识别，首次配对后浏览器会保存信息并自动重连。需要时可取消桌面队列选项，使用浏览器内的 qwen3.7-plus / qwen3.6-plus 模型。

## 本版更新

26.11.12-v1 将表格商品行接入六阶段流程详情，固定关闭和返回表格按钮，提供当前步骤、图片、平台状态、供货资料与处理记录定位；候选占满宽度并支持全部分组翻看。处理/等待原因及时回写原表行；青创网等待同次搜图最多45秒并补回调缺失时的响应读取，不重复提交不确定请求。在线表服务端任务门禁仍需单独部署。

26.11.10-v3 修复淘宝/天猫来源商品页已打开但未能读取主图的问题：直接读取商品轮播高清图和懒加载图片地址，优先采用放大图并过滤缩略图及店铺/推荐图片。

26.11.10-v4 新增高相似候选价格参考，匹配分至少90的同款或相似款候选按价格排序并保留各平台商品链接。供应商资料优先回填页面已采集字段，表单明确显示当前平台与来源链接；详情图分散取样以覆盖后续尺码表。本地构建同时包含在线表任务绑定和历史任务范围修复，服务端门禁仍需单独部署在线表服务。

26.11.08-v3 修复抖音分享商品页读取不到主图：采集器会读取商品轮播的 CSS 背景图和页面标题，并等待动态商品页继续加载，最多约 20 秒；若仍无法读取主图，会明确提示采集失败，不再归类为登录问题。对之前卡住的任务，升级后点击“继续原任务”重试即可。

26.11.08-v2 修复来源采集长期等待，任务会提示插件未连接、版本待确认、需要更新或页面超时，并提供处理指引与继续原任务入口。在线表格、本地表格和单链接可从分享文案中自动提取商品链接。升级后须在“使用说明”更新插件文件，再到 Chrome / Edge 扩展管理页点击重新加载并重新打开插件工作台。批量导入与队列暂停/继续保持可用；异常商品仍需逐条继续。

## 默认的自动买手流程

平台覆盖说明：自动买手固定调度网商园、17网、青创网和衣衫汇；手动搜图工作台首次默认全选四站，可按需取消。每站显示本次返回候选数、平台报告总数和搜索状态；桌面识别批次另列进入本批的候选数，买手详情同时显示可用数量。平台超时或未选择不等于没有商品；缺少报告总数时显示未知。17网准确搜与相似搜的报告合计可能重复，分组单独保留。衣衫汇 `.cn` / `.com` 均统一使用 `e3hui` 平台标识，避免在买手链接校验时被误丢弃。历史任务缺失的原始返回统计不会凭候选列表补造。

先使用 TDL 账号登录桌面端并在浏览器登录对应平台。视觉模型默认由服务端托管；互拓连接在服务端按 TDL 用户映射，每位买手的互拓账号由管理员维护一次，普通用户无需填写接口、OAuth 或 ERP 账号密码。

1. 导入 XLSX、CSV 或 TSV，表格只需商品链接，无需图片；也可添加单个链接。
2. 确认导入后自动打开来源网页取主图，再搜索四个供应平台、核对同款并获取供货资料。
3. 读取淘宝套图及互拓类别/字典，按供应商证据整理颜色、尺码、成分、成本和动态属性。
4. 完整商品自动保存互拓草稿，再按实际版本转入待审核并回读编码。结果保留原文件、工作表与行号，支持 CSV 回填导出。
5. 多供应商同款、重复来源、已存在互拓记录、缺成分/尺码图/质检材料、无法确认同款和登录验证等进入待处理区，队列继续下一件。

每条链接显示六阶段进度、当前步骤、异常原因和互拓回执。正常任务不再逐条要求人工开始识别或确认。下文的人工审核和手动搜图说明仍适用于辅助工具及历史识别记录。

## 安装与使用

1. 打开 `edge://extensions` 或 `chrome://extensions`，开启开发人员模式。
2. 加载解压缩的扩展目录 `D:\A_Electron\ProductComparison`。搬移后选择包含 `manifest.json` 的新目录。
3. 更新源码后，在扩展管理页重新加载，关闭旧工作台，再从扩展图标打开，确认显示 **v26.11.12-v1**。
4. Electron 默认托管模型由 TDL 登录身份自动启用，无需填写 API Key。若切换到浏览器内识别，再展开“视觉大模型设置”填写自己的 API Key。
5. 在需要的平台完成登录和搜图权限确认；默认只选网商园，其余平台可独立勾选。
6. 选择、粘贴或拖入商品图，自动开始平台搜图；检查候选后点击“确认候选并开始识别”，才会调用模型。

候选图按平台地址自动获取，不要求逐个打开商品页。青创网会移除平台返回地址上的 OSS 缩略参数；衣衫汇优先使用页面明确标记的原图，并尝试已观察到的 `_450.jpg` 原图变体。所有图片按实际尺寸检查；低清图会停止识别，不会放大缩略图后冒充原图。搜图完成后需人工核对候选并确认开始识别。每次更新将 `-v` 序号加一（本版 26.11.12-v1），打包脚本检查扩展与桌面版本一致。

视觉识别默认使用 3 批并发，每批最多 4 张候选。桌面端遇到未完成候选时自动重试最多 3 次，成功结果与人工审核不会重复提交；额度耗尽后停止，点击“重试未识别候选”启动新一轮识别，并恢复 3 次自动重试额度。计数随原任务持久化，重复点击合并，不新增任务。浏览器扩展独立识别仍保留原有暂停行为。

识别结果页默认“推荐先看”，优先疑似同款，再看相似款、无法判断，同类按匹配分降序；未识别归入“需重试”。按整批最高模型分动态排除：最高分至少 90，排除 85 分以下；最高分 85～89，排除 70 分以下；更低时沿用 50 分及以下排除。85 和 70 的边界分保留。排除只影响视图，不删除候选、证据或导出记录。

搜图完成后，点击 **“确认候选并开始识别”** 才把合格候选交给模型；已识别的商品不会重复发送。刷新页面不会自动重新调用平台或模型。

### 模型建议与人工确认

桌面批次卡片分别显示待人工核对、需重试、已排除和确认同款，总候选数作为次要信息。结果行显示平台和已知检索类型，支持平台及状态筛选；历史记录未保存准确/相似类型时只显示“图片搜款”。

人工审核以“确认同款并继续 / 排除候选 / 无法判断”为主，不要求重新评分；备注可选。确认供应商同款后进入资料采集；淘宝候选则回到买手任务选作套图来源。原有手动分类、参考分调整保留在“补充审核选项（可选）”中。

优先比较品类、廓形、领口、门襟、袖型、口袋、下摆、拼接、图案位置、纽扣与装饰。颜色、光线和背景差异通常不影响同款判断；只有同时对应明显面料、图案、结构或工艺变化时才构成重要差异。匹配分只用于排序，不代表同款概率。

“模型建议模式”仍保留暂定结论语义，模型完成数不等于人工确认数；人工结论优先，切换模式、筛选、审核和导出不调用模型。
扩展按图片独立保存结果和模式；重新搜索只替换当前图片的结果。审核只对当时的商品、图片和模型响应有效，重新识别或更换商品不会继承旧审核。Electron 每个任务也有相同的模式与审核入口，完整 JSON 导出按最终分类和同类匹配分排序，同时保留原始建议、人工记录、`finalVerdict` 和 `finalScore`（0～100，未审核的人工模式为 null；无法判断时分数也为 null）。旧审核没有单独人工分数时沿用当时模型分数。从扩展提交新任务时沿用工作台所选的结果模式。

界面展示“采纳模型 / 纠正”数量，供人工检查模型表现；这些数量不等同于经独立标注验证的准确率，人工记录也不会自动训练或修改模型。建议先覆盖同款、相似不同款、遮挡及不同拍摄角度，再决定何时切换直出。

API Key 只保存在扩展后台的受限 `chrome.storage.session` 中，设置页输入框保存后立即清空，不进入项目源码、商品页面、持久结果、模型提示词或诊断。重启浏览器、重新加载或更新扩展后可能需要重新填写；“清除 Key”可主动移除。浏览器扩展会话存储不等同于操作系统密钥保险箱。

直接双击 `workbench.html` 只能预览界面，不能搜索或比对。

### 平台连接检查

工作台顶部固定显示“平台连接”卡片，逐个平台显示状态、简短原因和处理入口。检查前为“未检查”，检查期间禁用平台跳转，检查结束显示检查时间；需要登录、权限不足和页面超时分别提示。详细 JSON 仅通过“导出诊断”下载，不显示在连接区。

“检查平台连接（不搜图）”会逐平台显示简短结果和处理原因，可点击“打开平台”进入官网。没有打开对应页面时显示“未打开”；只有登录页或可见登录表单才显示“需要登录”；衣衫汇明确禁止搜图时显示“无搜图权限”。页面检查超时显示“页面未响应”，不能据此判断未登录。多个页面检查达到总时限时保留已完成结果。

页面已响应只说明扩展可以读取页面，不代表已验证登录、搜图额度或接口权限。本功能不上传图片、不读取账号字段或 Cookie；详细技术信息仅通过“导出当前诊断”下载。桌面端 TDL 登录和各货源平台账号独立，各平台需要自己的登录和搜图权限。

## Electron 本地桌面端（预览版）

桌面端与浏览器插件分工运行：插件继续使用用户现有浏览器登录态完成平台搜图；Electron 在本机接收候选、保存任务和结果、下载并压缩图片、维护串行队列，再将每批图发给用户选择的视觉模型服务。视觉模型仍在线推理，桌面化不会变成离线识别；本地化的是队列、图片处理、结果页和任务恢复，减少扩展后台长期处理几百张图片的压力。

在项目根目录运行（开发模式）：

```powershell
npm.cmd --prefix desktop install
npm.cmd --prefix desktop run dev
```

首次启动后，使用现有 TDL 账号与密码登录。后台托管视觉模型会按账号自动启用，使用 `gpt-6.1-sol` 和中等推理；服务密钥只保存在云端服务器。设置页可以添加其他 OpenAI 兼容模型，API Key 通过 Windows 安全存储按账号加密；支持编辑、删除、切换和测试图片输入。软件更新位于“设置”下方，登录后检查版本；发现新版时可以忽略本次公告，或点击进入下载更新。

“设置 → 模型使用情况”打开 `https://wsfile.cn/maishou/admin/`。普通账号只能查看自己的托管模型用量；TDL 管理员可查看账号汇总并按账号查看明细。页面只存请求状态、Token 和耗时汇总，不保留提示词、图片或密钥。

登录后首先打开“商品录入与处理”：先从云端共享选品表、本地运营表或单链接录入，任务随后在同页自动推进，完成项和异常集中查看；“识别与复核”用于辅助搜图流程的模型比对和人工判断；“抖音主图”是按需使用的图片下载工具。在线选品表托管在找商品自己的云服务器，管理员创建后所有 TDL 账号免填服务器地址和表格访问令牌即可使用。

在线任务固定关联原在线表 ID、行 ID、任务 ID 和商品链接；表格处理状态与任务卡片都显示任务 ID，卡片可“定位原表行”。默认只显示当前表格与本地录入的任务，已删除行与其他表格的任务可切换“全部历史任务”查看。继续处理前和每个自动步骤都会核对原行与商品链接；旧行删除、任务被其他设备接管或链接不匹配时会停止，不能沿用旧资料处理新商品。旧任务只在完整核验后补齐在线表 ID。表格导出和本地回填导出均增加任务 ID、在线表 ID、在线行 ID 三列，原有“表格ID”仍是商品目录编号。

待处理、已完成、已停止或尚未启动的任务可“删除本机任务”，执行中的任务和结果未知的请求需先处理完成。删除需要确认，会清理本机任务与主图、停止关联浏览器命令，保留在线表格的原任务 ID、处理回执、互拓商品、独立识别记录与商品资料文件夹；新商品应另增表格行并确认提交。上述关联保护需同时更新桌面端与在线表服务源码，本次源码修改不等于安装包或线上服务已更新。

“工作台”集中展示任务进度和人工审核，“设置”集中管理模型、插件配对和账号信息。首次在扩展工作台输入桌面端长期配对码并连接；配对码由 Windows 安全存储加密，浏览器会把配对信息保存在本机并自动重连。桌面端退出登录后本地服务暂停，重新登录后配对码仍有效。每次最多接收 500 个候选、每批比较 4 张；考虑串行请求耗时，仍建议每次提交 100～200 张。

登录通过 HTTPS 复用 TDL `/myladmin/api/auth/login`、`me`、`logout`，不在应用里直连数据库或保存账号密码。勾选“保持登录”后，仅把登录会话通过 Windows 安全存储加密落盘；重启需在线验证会话，失效或撤销后回到登录页。退出会撤销当前应用会话、停止在途比对并关闭本地桥；该账号长期配对码仍保留，加密保存且仅在重新登录后启用，不会退出其他 TDL 客户端。

本地服务仅监听 `127.0.0.1`。API Key 由主进程使用 Electron `safeStorage`（Windows DPAPI）加密保存，不返回渲染界面或插件；系统加密不可用时拒绝保存，不降级明文。不同云端账号的模型、任务和审核分别保存在用户数据目录的 `profiles/<账号哈希>/`，`models.json` 仅含加密 Key，`jobs/jobs.json` 保存任务和结果，`jobs/queries/` 保存原图；不会云端同步。旧版未登录的 `jobs/` 保留，避免自动归属给错误账号。不要将包含个人任务和加密凭据的用户数据目录随安装包分发。

每个账号最多保留最近 10 条任务。进行中的任务锁定所用模型；退出或关闭应用时会取消请求并保留已有结果，在途请求不自动重发，未完成项可手动重试，服务已受理的请求仍可能计费。重启或再次登录恢复队列前会验证 TDL 会话。候选图从公开 HTTPS 地址下载并在本机压缩，随后与原图一起发给选定模型。

### 任务时间与删除记录

桌面端每批任务显示创建时间和最近更新时间（北京时间，精确到秒），重试会作为新批次显示。历史任务没有有效时间时显示“时间未记录”，不补造时间。每批可点“删除本批记录”，或在任务区点“清空记录”；确认弹窗会列出创建时间、任务名和候选数量。清空仅针对弹窗所列的已结束记录，排队或识别中的任务保留。删除会清理该批识别结果、人工审核、原图和缓存图片，不影响其他账号、模型或配对配置；写盘失败会回滚记录，文件清理失败会明确提示。

侧边栏版本由主进程返回：安装版读取运行程序的实际包版本，开发模式读取扩展清单版本，界面不再写死为 v1。当前源码为 v5；本轮按要求未生成安装包，已有安装包保持原样。

### 高清图片与失败恢复

青创网带 `x-oss-process` 缩略参数的公开商品图优先获取去掉该参数的图片；签名或带令牌的地址保持原样。已抽查的 200×200 图片可取得 800×800 或 1800×1800 的清晰来源，不必为这些图片逐个打开详情页。其他平台不猜测未经验证的原图路径；仍需登录或无法获取的图片会明确失败，不绕过平台权限。

所有候选先解码检查尺寸：长边至少 600、短边至少 320 像素，否则标为“细节不足，未执行识别”。这是最低尺寸要求，不保证图片没有模糊、遮挡或缺少关键角度。送模图片不放大，最长边最多 1600 像素，JPEG 质量 92。桌面端也检查用户原图尺寸。

桌面端将实际送模候选图片保存到账号的 `jobs/images/<任务ID>/`，记录来源尺寸、送模尺寸与 SHA-256。人工审核和“放大查看”读取同一份本地图片并校验文件，审核签名包含图片哈希；保留最近 10 个任务时同步清理对应图片。“重试未识别候选”直接续跑原任务，只提交未完成图片，保留任务编号、创建时间、成功结果和人工审核；连续点击或识别中重复提交不新增任务，卡片记录重试次数及时间。旧任务未保存送模图片，会提示旧结果可能来自缩略图；“用高清图逐张重新比对”是主动重做全部图片，会创建新任务、保留原记录，并重新产生模型费用。

桌面进度展示成功比例，并分别统计“已识别 / 失败 / 尚未识别”。模型请求失败后只标记实际提交的本批，后续候选保持尚未识别并暂停，不自动重发。点击“逐张重试未完成候选”创建独立任务，每次只提交一张候选与原图，跳过原任务的成功商品；刷新、放大图片和人工审核不调用模型。HTTP 504 显示“模型网关等待上游超时”，它本身不能证明账号登录或模型权限有问题。

如果平台图片地址已过期、需要登录 Cookie 才能读取或不可公开访问，本机下载会失败并将该候选标为未完成；不会把浏览器 Cookie 带给 Electron。配对码由 Electron 通过 Windows 安全存储加密后按 TDL 用户档案保存；浏览器扩展的本机存储会保留配对码以便自动连接，清除扩展数据或更换浏览器后需要重新配对。Windows 安装包由 `npm.cmd --prefix desktop run dist:win` 生成；未签名安装器可能显示 Windows SmartScreen 提示。

## 青创网结构化字段

青创网优先按官方搜图页已确认的 `Result.Items` 精确读取 `ProductId`、`ProductName`、`ProductNo`、`DefaultPrice` 和 `Photo`，减少对页面卡片样式的依赖。另保存并展示页面明确使用的新品、共享仓、自营仓、云仓闪发、工厂直供和闪电发货标签。图片相对路径以公开 CDN 地址解析；模板解析保留为回退，未知数组不递归猜测。接口与模板都无法确认结果时明确报错，不冒充空结果。

本次真实登录页只用一张合成服装图进行 1 次搜图，看到 24 个候选并读取官方模板字段；抽查一个商品原图实际下载到 1920×1920。证据是页面 DOM 和官方模板，未捕获原始 JSON 响应，未证明长期稳定性。商家编号、店铺地址、库存等未确认字段不推断填充。搜图仍不自动调用模型，识别需人工确认。

## 多图细节比对

平台结果先到先展示；通过商品基础完整性、去重和当前价格条件的候选进入大模型比对。**每批 1 张原图 + 最多 4 张候选图，共最多 5 张图**；候选更多时顺序分批，每批独立重复提供原图。这个数量是本项目为细节可读性和请求体大小设置的批量大小，不是供应商公布的模型最大张数。

- 每张候选图片有独立编号；响应按编号关联，不能依赖模型返回顺序。编号缺失、重复或未知时拒绝该批，避免串到其他商品。
- 模型重点核对领口、袖型、门襟、口袋、下摆、图案位置、拼接、纽扣和装饰等可见细节。人物、背景、姿势、衣架和水印不作为同款证据；照片不能证明面料成分、隐藏结构或同一 SKU。
- 返回 **疑似同款 / 相似款 / 明显不同 / 无法判断**，并逐张展示吻合点、差异和待核实细节。疑似同款至少需要两条独立吻合依据；存在未确认的关键细节时降为相似款。
- 排序先看结论，同类结论内再看模型给出的 0～100 排序分。分数不是同款概率或准确率；“明显不同”不会因为分高而挤到“疑似同款”之前。
- 人工确认后，所有满足基础和价格条件的候选都会进入模型流程，没有像素相似度或向量相似度预筛选。明显不同和无法判断的商品仍可查看，不自动购买或断言同款。
- 每批完成后立即更新并保存。接口鉴权、额度、网络或响应格式失败时停止本轮后续模型请求；桌面端区分本批失败与后续尚未识别，浏览器模式统一计入未完成识别。不自动重试，不降级成像素分。图片下载失败或尺寸不合格只影响对应商品，不产生模型判断。

### 几百张图片怎么跑

软件允许一次搜索最多保留 **500 个候选**，但这不是建议一次点击完成的数量。每次模型请求包含 4 个候选，500 个候选会产生最多 125 次串行模型调用；按单次请求几秒到几十秒估算，整体可能持续几十分钟，并受账号频率、额度和图片失效影响。

实际使用建议每次控制在 **100～200 个候选**：100 个候选约 25 次调用，200 个候选约 50 次调用。检查候选后点击“确认候选并开始识别”；已经成功的结果会保存，后续只重试失败项。单批最多 4 张候选，下载和解码只保留当前批，避免几百张图片同时占用浏览器内存。500 个候选是保护上限，超过后不会下载图片，也不会调用模型。

阿里云官方资料确认这两个模型支持图片理解；单次请求可以在 `user.content` 中提供多个 `image_url` 对象，用于商品对比。官方上限会因传输方式和模型而变化，且所有图片共享图文 Token 预算；本项目使用压缩后的图片和每批 4 张候选，不依赖官方的数百张上限。请以[图像与视频理解及多图输入](https://help.aliyun.com/zh/model-studio/vision)的当前说明为准。Coding Plan 的[服务说明](https://help.aliyun.com/zh/model-studio/coding-plan)明确限制其 Key 用于自定义应用或自动化脚本，本项目只接受百炼标准 API Key。

**图片传输范围**：平台搜图会把原图上传至勾选的批发平台；大模型比对会另外把原图和候选图发送至所选阿里云接口。模型输入仅包括图片、候选临时编号和固定比对要求，不发送商品价格、供应商、平台 Cookie 或账号资料。

## 多张商品图一起搜索

点击 **批量添加图片**，或一次拖入/粘贴多张图片。每组最多10张，一张图对应一个独立商品：裤子、上衣各有原图、候选、成本、款号和人工审核记录，不合并成一次模型判断。批量添加单张也只导入预览；原有“选图并搜索”仍可直接发起单图搜图。

1. 添加后点击缩略图切换，逐张填写款号；需要降本时为该图选择模式、填写成本。批量新图默认不带前一张的成本或款号。
2. 点击 **依次搜索未搜索图片**。逐张调用所选平台，两张图之间间隔1秒；单张内部保留原有的平台并行。平台出现额度、认证或权限限制后，当前批后续图片跳过该平台；没有可用平台或所有平台失败时暂停，避免连续消耗请求。
3. 逐张查看候选，再点击当前图的 **确认候选并开始识别**，或 **确认全部待识别图片**。识别可能计费，搜图和导入均不自动调用模型。桌面端按图片生成独立任务，标题显示图片名；保留共同组标识和各自图片标识。已识别、已移交候选不会重复发送。
4. **暂停队列** 保留已返回结果，未开始图片可继续；失败或主动停止的当前图可点击“重新搜索当前图”明确重试。刷新只恢复记录，不自动续跑或重发请求。
5. **移除当前图片 / 清空图片队列** 删除浏览器本地图片和对应结果，已有搜索记录需确认；桌面任务由桌面历史记录另行管理。**重置当前图** 只清除当前图片，其他图片保留。

性能边界：单张源文件不超过20MB、5000万像素，宽高均至少100像素；逐张解码、关闭位图，最长边压到1200像素，不放大小图。重复图片按压缩内容指纹跳过，损坏文件单独提示并保留已有图片。多图记录放在 IndexedDB，列表仅持有缩略图和进度，一次只载入当前图的完整候选；写入失败会暂停批量推进并保留当前可见结果。桌面端同时最多10个排队/处理任务，满时暂停提交，等待后手动继续。

## 两种工作模式

- **一张图选供应商**：无需成本。款号全等只辅助排序，不证明同款。
- **已有成本，找低价商品**：填写当前成本和至少节省金额，默认至少省 5 元；采购价必须低于当前成本并满足节省条件。金额按整数分比较，最多两位小数。价格条件不通过的商品不消耗大模型请求。

缺少商品 ID、有效图片地址、详情链接或有效价格的记录进入淘汰明细；同平台重复商品去重。默认显示前 8 条，其余结果可展开。结果汇总分别统计疑似同款、相似款、明显不同、无法判断和未完成识别数量。

平台报告总量与实际收到数量分开显示。采购价未含运费、税费、包装等额外成本，详情需在平台登录状态下核对。

## 停止、重置与恢复

- “停止搜索并保留已返回结果”停止等待平台与大模型，断开本轮模型端口并中止 HTTP 请求；已经提交的图片无法撤回，已消耗的调用不保证退还。
- “重置”清空图片和商品结果，等待清空状态保存后恢复操作；模型会话设置独立保存。
- 旧请求不会覆盖新搜索，也不会提前解除新一轮操作锁。
- 刷新保留已保存的图片与商品。平台搜图不会自动调用模型；确认识别后中断时保留结果，只可继续处理未完成项。
- 存储失败会提示，本页已返回的结果仍保留，但刷新可能丢失尚未保存的更改。

## 图片与请求边界

原图最大 20 MB、宽高至少 100 像素，工作台最长边压缩到 1200 像素。网商园另按官网流程生成短边不超过 300 像素的 JPEG；模型使用工作台原图，不使用这一小图。衣衫汇要求宽高至少 201 像素。

候选图片只从指定平台及已确认 CDN 的 HTTPS 域名下载，后台不携带 Cookie。浏览器单次下载含整个响应体的超时为 12 秒，最多 4 MB；仅对瞬时网络失败、超时或部分 5xx 额外重取一次，404 不重取。桌面端图片下载超时 15 秒、最多 12 MB，并在每次跳转前检查域名与公网地址。两端候选送模型前均检查最低尺寸、最长边缩小到 1600 像素；不会放大缩略图。浏览器模型请求超时为 90 秒，桌面端为 95 秒，响应最多 256 KiB；输出截断、格式错误或编号不完整不会当作成功。

模型请求通过扩展后台执行，只有本扩展的 `workbench.html` 可以配置或提交。长请求使用端口心跳维持 Manifest V3 后台，关闭工作台或停止任务会断开端口并取消请求。平台搜图有 110 秒收尾保护，青创网搜图等待同次请求最多45秒，回调缺失时尝试读取同次原生响应且不重复提交；多批模型比对可能在平台搜索结束后继续运行。

## 诊断与常见问题

- **未完成识别 / 未配置**：默认在桌面端模型设置中确认模型和登录；检查候选后点击“确认候选并开始识别”。若使用浏览器内模型，填写百炼标准 API Key 后再确认。
- **HTTP 401 / 403 / 429**：分别检查 Key、模型权限和额度/频率限制；处理后手动重试。
- **HTTP 504**：模型网关等待上游超时；桌面端可手动逐张重试未完成候选。不能仅据此判断登录失效，逐张重试也不保证上游恢复。
- **模型返回格式或编号错误**：本批保持未识别，不能把有歧义的判断回填给商品。可继续重试未完成项。
- **图片加载失败**：公开图片可能过期或返回 404，打开详情核对，不当作“不相似”。
- **某平台失败**：查看平台阶段与问题页；额度或认证限制需在对应平台处理。
- **扩展版本未变化**：重新加载扩展，关闭旧工作台后从图标打开。
- **测试找不到 Chromium**：运行 `npm.cmd run install:browser`，确认缓存设置一致。

“检查平台连接（不搜图）”只读检查已打开页面，不上传图片、不调用搜索。“导出当前诊断”在搜索或比对期间也可使用，只导出平台阶段、数量、模型与结论统计，不含原图、商品原始记录、API Key、Cookie 或账号资料。

## 客户端内置插件和使用说明

### 平台账号与登录

桌面“设置 → 平台账号”分别保存网商园、17网、青创网和衣衫汇账号。账号密码整包使用当前 Windows 用户安全存储加密，按 TDL 账号隔离；列表遮罩显示账号，不回显密码。编辑时密码留空保留原密码，更换账号必须重新填写密码。删除只删除本机配置，不注销平台账号。

插件搜图或详情采集进入对应 HTTPS 官方登录页时，仅在唯一明确的密码表单、账号输入框和登录按钮均可确认时自动填写并提交。密码只通过已配对的本机桥暂时读取，不写入插件存储、任务或日志。同平台五分钟内只尝试一次，失败不循环提交；验证码、滑块、扫码、未知或外域表单交人工处理。当前通过的是隔离页面与虚构账号测试，四站真实自动登录仍需按实际页面逐站验收。

### 买手工作台
登录后默认进入买手工作台，主要入口为导入表格和添加单个链接。手动搜图、补录和高级连接设置折叠收纳。默认每次只显示 50 个任务，支持筛选待处理/队列/已完成并继续加载，减轻大表格的渲染负担。

买手工作台同时提供在线选品表：连接 `table-server` 后，多台桌面端可以分页读取和编辑同一张表。每行使用版本号防止覆盖，人工点击“确认并提交”后才会领取并创建买手任务；处理状态和互拓编码会回写到原行。支持本地 XLSX 导入和在线 XLSX 导出。在线服务的启动、TDL Bearer 校验、SQLite WAL、索引和部署边界见 [table-server/README.md](table-server/README.md)。

测试固定字段时可在买手工作台下载“买手上架测试模板”。表格保留选品日期、表格ID、图片、平台链接、供应商比较信息、运营商品编码、互拓编码、操作人、备注、状态和商品目录等字段。运营商品编码与互拓返回编码分列保存。设置“买手资料根目录”后，每件商品初始保存为 `买手/月份.日期/表格ID`，取得互拓编码后自动改名为编码目录；每个目录保存主图和 `商品记录.json`，其中保留来源、供应商证据、套图链接和处理状态。

供应商数据和营销套图分别留存。模型不得猜填成本、库存、成分比例和质检结论；普通文字事实需要连续引文支持，图片 OCR 事实需要独立复核。自动同款条件为视觉匹配分至少92、疑似同款且没有明确差异或不确定项。低分候选按识别批次最高分动态归入排除视图。

当前完成了本地流程、受控全链路与真实互拓字典的只读联调。四站真实详情完整性、淘宝连续搜图、真实商品提交及大模型质量仍需使用业务链接现场验收。互拓现有商品追加套图和全库图片查重缺少已接通契约，相关情况保留为例外，不自动覆盖原商品。

客户端“使用说明”提供从插件安装到人工审核的完整步骤。安装包内包含同版本插件，无需另行联网下载；点击“准备插件”会将插件复制到当前 Windows 用户的固定应用数据目录，页面支持打开文件夹、复制目录和 Chrome / Edge 扩展页地址。开启浏览器开发人员模式并手动加载该目录即可。

升级桌面端后，页面显示内置插件与已准备插件的版本差异。点击“更新插件文件”后，在浏览器扩展卡片手动重新加载；固定目录不会随版本变化，从而保持同一浏览器资料中的扩展 ID 和配对存储。插件未在商店上架，客户端不自动替用户操作浏览器安装或重新加载。

## 抖音商品主图

桌面端“抖音主图”支持批量粘贴抖音商城商品分享文案、短链或详情链接，选择保存目录和 PNG / JPEG 后下载。每个商品单独保存图片及商品信息，结果列出成功、部分失败和原因；停止保留已下载图片。使用已安装的 Chrome 或 Edge 独立临时浏览器解析，不需要额外安装 Python，不读取日常浏览器资料。平台可能要求登录或验证，此时不会绕过平台限制；实际图片质量以返回内容为准。

下载完成后系统自动将第一张图片交给已配对扩展，并使用当前浏览器的登录状态只对该图片依次查询网商园、17网、青创网、衣衫汇，不会启动其他暂存图片。搜图不会自动调用模型，模型识别仍由用户确认开始。候选经人工确认“疑似同款”后，桌面端自动排入浏览器详情采集，扩展从对应供应商商品页采集页面可见字段、文字和 HTTPS 图片链接并关联到原候选；其余结论不会触发详情采集。页面未公开的规格或被登录验证拦截的信息会明确缺失，不会绕过平台权限。完整结果 JSON 包含 `productDetails` 和图库链接。
